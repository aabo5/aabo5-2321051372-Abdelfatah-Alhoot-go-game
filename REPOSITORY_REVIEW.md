# Repository Review and Suggested Improvements

A code review of the Go Game repository with specific, actionable findings.

## Code Quality Issues

### 1. Coordinate axes are swapped in GameScreen.handleClick()

**File:** `GameScreen.java`, line 164–165

```java
int i = Math.round(evt.getX() / cellWidth);
int j = Math.round(evt.getY() / cellHeight);
networkClient.sendMove(i, j);
```

`i` is computed from the X axis (columns) and `j` from the Y axis (rows), but `GameLogic.placeStone(r, c, player)` expects row first, column second. So `i` (X/column) is being sent as the row, and `j` (Y/row) as the column.

The game still works because the server and client both apply this same transposed mapping consistently — but the coordinates displayed in the move history (`"1. BLACK → (3,4)"`) show column,row instead of row,column. This is confusing and could cause bugs if someone adds features that depend on correct coordinate semantics (like displaying row/column labels on the board).

**Fix:** Swap the arguments: `networkClient.sendMove(j, i);`

### 2. Unused fields in GameScreen

**File:** `GameScreen.java`, lines 17–18

```java
private int[][] board = new int[9][9];
private int currentPlayer = 1;
```

These fields are never read or written after initialization. The board state comes from `game.getBoard()` (the `GameLogic` instance), and turn tracking is handled by `isMyTurn` and the server's `TURN:` messages. These are leftover fields from an earlier local-play implementation.

**Fix:** Remove both fields.

### 3. GameLogic(int size) constructor ignores its parameter

**File:** `GameLogic.java`, lines 139–142

```java
public GameLogic(int size) {
    // SIZE is a compile-time constant; this constructor
    // exists for compatibility with GameScreen
}
```

This constructor accepts a `size` parameter but does nothing with it. `SIZE` is a `static final int = 9`. `GameScreen` calls `new GameLogic(9)`, but the parameter is discarded. If someone passes `13` expecting a 13×13 board, they'd silently get a 9×9 board.

**Fix:** Either remove this constructor and use the default one in `GameScreen`, or validate that `size == SIZE` and throw an exception if it doesn't match. The comment already acknowledges this — it just needs to be cleaned up.

### 7. Font and cursor paths are relative — fragile across environments

**Files:** `FontUtil.java`, `GameScreen.java`

Both `FontUtil.loadFont()` and `GameScreen.initCursors()` resolve resource files using relative paths like `"resources/fonts/Retro-Gaming.ttf"` and `"resources/images/hand_black.png"`. These paths depend on the working directory being set to the `GoGameClient` folder.

When running from an IDE, the working directory is usually the project root, so the paths work. But when running from a JAR or from a different directory, the files won't be found.

**Fix:** Load resources from the classpath using `getClass().getResourceAsStream()` instead of `new File()`. This requires moving the resources into `src/main/resources/` so Maven packages them into the JAR.

### 8. No input validation on MOVE coordinate parsing

**File:** `ClientHandler.java`, lines 81–83

```java
String[] parts = line.substring(5).split(",");
int r = Integer.parseInt(parts[0]);
int c = Integer.parseInt(parts[1]);
```

If a malformed `MOVE:` message is sent (e.g., `MOVE:abc`), this will throw a `NumberFormatException` that's caught by the generic `IOException` handler — but it's not an IO error. A malicious client could send garbage move strings.

**Fix:** Wrap the parsing in a try-catch for `NumberFormatException` and `ArrayIndexOutOfBoundsException`, and send `INVALID_MOVE` on parse failure.

---

### 9. No bounds checking before placeStone

**File:** `GameSession.java`, line 60

```java
boolean valid = game.placeStone(r, c, currentTurn);
```

If a client sends `MOVE:100,200`, `placeStone` will throw an `ArrayIndexOutOfBoundsException` because the board is `int[9][9]`. The `isInside()` check exists in `GameLogic` but is not called before `placeStone` — and `placeStone` itself doesn't call it.

**Fix:** Add `if (!game.isInside(r, c))` check in `handleMove()` before calling `placeStone()`, or add it at the top of `placeStone()`. Also make `isInside()` public (it's currently package-private).

---

### 10. isSocketClosed() doesn't detect half-open connections

**File:** `ClientHandler.java`, line 51

```java
public boolean isSocketClosed() {
    return socket.isClosed();
}
```

`Socket.isClosed()` only returns `true` if `close()` was called on the local side. If the remote client quietly drops (e.g., network failure, process killed), the socket stays open until the next read attempt fails with an `IOException`.

This means `GoServer`'s `waitingPlayer.isSocketClosed()` check might not detect that the first player left while waiting. In practice, this is mitigated because the `ClientHandler` thread is already running and will catch the disconnection on its next `readLine()` call — but the lobby check in `GoServer` can still pair a dead player.

**Fix:** Consider adding a heartbeat or using `Socket.setSoTimeout()` on the waiting player's socket.

## Structural Suggestions

### 1. Extract GameLogic into a shared module

`GameLogic` lives in the `GoGameClient` package, but it's used by both client and server. This creates a circular conceptual dependency — the server module depends on the client module just for the rules engine.

**Suggestion:** Create a third Maven module (e.g., `GoGameCommon`) containing `GameLogic`, and have both client and server depend on it. This makes the dependency direction cleaner and would let you split the packages more naturally.

### 2. Move resources into src/main/resources

The `resources/` folder sits outside the Maven standard directory layout (`src/main/resources/`). Moving fonts and images into `src/main/resources/` would let Maven package them into the JAR, and they could be loaded from the classpath instead of fragile relative file paths.

### 3. Add a parent POM

Both modules share the same `groupId`, Java version, and Maven compiler plugin configuration. A parent POM at the repository root would eliminate this duplication and let you build both modules with a single `mvn clean install` from the root.

### 4. Add .gitignore entries for target directories

The `.gitignore` already includes `/GoGameClient/target/` and `/GoGameServer/target/`, which is correct. The `target/` directories in the repository suggest they were committed before the gitignore was added — they should be removed from tracking with `git rm -r --cached`.
