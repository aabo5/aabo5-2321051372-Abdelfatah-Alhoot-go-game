# Contributing

Guidelines for contributing to the Go Game project.

## Getting Started

1. Fork the repository.
2. Clone your fork locally.
3. Follow the [Installation Guide](INSTALLATION.md) to set up the build environment.
4. Create a feature branch from `main`:
   ```bash
   git checkout -b feature/your-feature-name
   ```

## Build and Test

Before submitting any changes, make sure the project builds without errors:

```bash
# Build client first (server depends on it)
cd GoGameClient
mvn clean install

# Build server
cd ../GoGameServer
mvn clean package
```

There are currently no automated tests. If you add tests, place them in the standard Maven test directories:
- `GoGameClient/src/test/java/com/mycompany/gogameclient/`
- `GoGameServer/src/test/java/com/mycompany/gogameserver/`

Manually test your changes by running a server and two clients to verify gameplay still works correctly.

## Code Style

- **Java version:** Target Java 17. Don't use preview features.
- **Package names:** `com.mycompany.gogameclient` for client classes, `com.mycompany.gogameserver` for server classes.
- **Naming conventions:** Standard Java — `camelCase` for methods and variables, `PascalCase` for classes, `UPPER_SNAKE_CASE` for constants.
- **Indentation:** 4 spaces, no tabs.
- **Comments:** Write comments to explain *why*, not *what*. The code itself should be readable enough to show what it does.
- **Swing threading:** All GUI updates from non-EDT threads must use `SwingUtilities.invokeLater()`. Any new network callback that touches Swing components must follow this pattern.

## NetBeans Form Files

The three `.form` files (`StartScreen.form`, `GameScreen.form`, `EndScreen.form`) are generated by the NetBeans GUI Designer. The `initComponents()` methods in the corresponding Java files are auto-generated and should not be edited by hand.

If you need to change the layout of a screen:
- Open the `.form` file in NetBeans.
- Make your changes visually.
- NetBeans will regenerate the `initComponents()` method.

If you don't have NetBeans, add your UI logic in the constructor *after* the `initComponents()` call, or create new components programmatically.

## What to Work On

See the "Future Improvements" section in the [README](README.md) for a list of features that would be good additions. Some good first contributions:

- **Add unit tests for `GameLogic`** — liberty checking, capture detection, suicide prevention, and territory scoring are all pure functions that can be tested without networking.
- **Fix the coordinate swap** — `handleClick()` currently sends `sendMove(i, j)` where `i` is derived from `evt.getX()` and `j` from `evt.getY()`, but `GameLogic` treats the first index as the row (Y axis). The game still works because both client and server use the same mapping, but it's conceptually backwards.
- **Replace rectangles with circles** — stones are drawn as `fillRect`. Switching to `fillOval` would look much closer to a real Go board.
- **Add ko rule enforcement** — store the previous board state and reject moves that recreate it.

## Submitting Changes

1. Push your branch to your fork.
2. Open a pull request against the `main` branch.
3. Describe what you changed and why.
4. Include screenshots if you changed any UI.
5. Make sure the project builds cleanly.

## Project Layout

If your contribution adds new classes:
- Client-side classes go in `GoGameClient/src/main/java/com/mycompany/gogameclient/`.
- Server-side classes go in `GoGameServer/src/main/java/com/mycompany/gogameserver/`.
- Shared code currently lives in the client module (since the server depends on it). If adding more shared code, put it in the client module alongside `GameLogic.java`.

## Communication Protocol

If you add new commands to the network protocol, update the protocol tables in the README and make sure both client and server handle the new message type. The protocol is text-based — one message per line, parsed by string prefix matching in `NetworkClient.parseAndDispatch()` (client) and `ClientHandler.run()` (server).

## Reporting Bugs

Open an issue with:
- What you did.
- What you expected.
- What happened instead.
- Server and client console output if available.
